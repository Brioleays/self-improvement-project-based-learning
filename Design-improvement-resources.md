# Design Resources for a Developer — Summary

## The Problem I Am Solving

As a developer, I can build things, but my design decisions are often weak. I want to reduce my dependency on AI for coding while still improving the visual quality and engagement of what I build.

## The Resources I Am Keeping

These are the sites I have vetted and plan to use.

### Godly
- **Link:** https://godly.website/
- **Why:** Shows animations, hover effects, and full interactive experiences via video. Best for learning motion design.

### Awwwards
- **Link:** https://www.awwwards.com/
- **Why:** The highest standard for design and innovation. Best for benchmarking against world-class work.

### Codrops
- **Link:** https://tympanus.net/codrops/
- **Why:** Tutorials that teach how to build advanced interactions with code. Best for learning the technical execution of design ideas.

### Minimal Gallery
- **Link:** https://minimal.gallery/
- **Why:** Curated clean and minimalist web design. Best for refreshing my taste when things feel cluttered.

### CSS Design Awards
- **Link:** https://www.cssdesignawards.com/
- **Why:** Rigorous awards platform with categories for UI, UX, and Innovation. Best for understanding what "polished" actually means.

### Lazyweb
- **Access:** Via MCP in Cursor or Claude Code
- **Why:** A library of 257,000+ screenshots from real products. It does not write code for me. Instead, it gives me design evidence — screenshots and reports showing how top products solved similar problems — and can review my work against those references. This is the tool I am most focused on because it teaches design thinking rather than doing the work for me.

## The Resources I Dropped

### Killer Portfolio
- **Reason:** Replaced by Lazyweb. Killer Portfolio was too narrow, only useful if I were building a portfolio site specifically.

### Hover States
- **Reason:** The original site appears to be defunct.

### Landbook
- **Reason:** Still active, but shifted from landing pages to general inspiration. Less focused than before.

## The Tool I Am Considering But Waiting On

### Claude Code with Lazyweb MCP
- **Cost:** Requires a paid subscription ($20/month or API pay-as-you-go). Lazyweb MCP itself is free.
- **Status:** I am waiting until I am ready for a larger project before committing to this cost.

## My Plan

1. Use Lazyweb to research design patterns before building any component.
2. Write the code myself.
3. Use Lazyweb to review my work and suggest improvements.
4. Only then consider fixing based on that feedback.

This keeps me in control of the code while improving my design judgment over time.
